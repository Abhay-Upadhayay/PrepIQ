# Project Documentation (PrepIQ)

This document provides a comprehensive overview of the architecture, stack, models, and API endpoints for the project.

## Tech Stack

**Backend**
*   **Runtime:** Node.js
*   **Framework:** Express.js
*   **Database:** MongoDB
*   **ODM:** Mongoose
*   **Authentication:** JWT (JSON Web Tokens), bcrypt for password hashing

**Frontend**
*   **Framework:** React
*   **Build Tool:** Vite
*   **Styling:** CSS (as per setup)

---

## 1. Backend Documentation

The backend is structured using an MVC-like architecture (Models, Controllers, Routes) with a clear separation of concerns.

### Directory Structure
```
backend/
├── src/
│   ├── config/        # Environment configurations and constants
│   ├── controllers/   # Request handling logic
│   ├── db/            # Database connection setup
│   ├── middleware/    # Express middlewares (e.g., authentication)
│   ├── models/        # Mongoose data schemas
│   ├── routes/        # Express route definitions
│   ├── services/      # Business logic (if complex enough to extract)
│   └── app.js         # Express app initialization
├── server.js          # Entry point of the server
├── package.json
└── .env
```

### Database Models

1.  **User** (`user.model.js`)
    *   Stores user profiles.
    *   **Fields:** `name`, `email` (unique), `password`, `targetExam`, `selectedSubjects` (array of strings).
2.  **Question** (`question.model.js`)
    *   Stores the main test questions.
    *   **Fields:** `exam`, `subject`, `topic`, `difficulty` ('easy', 'medium', 'hard'), `questionText`, `options` (array of 4 strings), `correctOption`, `explanation`.
3.  **AttemptSession** (`attemptSession.model.js`)
    *   Used to track when a user starts taking a mock or practice test.
    *   **Fields:** `userId` (ref: User), `type` ('mock', 'practice'), `subject`, `questions` (array of ObjectIds ref: Question), `startTime`, `durationSeconds`, `endTime`, `score`.
4.  **AttemptAnswer** (`attemptAnswer.model.js`)
    *   Records each individual answer given by a user for a question within a session.
    *   **Fields:** `userId` (ref: User), `sessionId` (ref: AttemptSession), `questionId` (ref: Question), `selectedOption`, `isCorrect` (Boolean), `subject`, `topic`, `attemptedAt`.
5.  **WeakAreaStat** (`weakAreaStat.model.js`)
    *   Metrics to identify subjects/topics the user struggles with.
    *   **Fields:** `userId` (ref: User), `subject`, `topic`, `totalAttempts`, `correctCount`, `accuracyPercent`, `lastUpdated`.
6.  **AIGeneratedQuestion** (`aiGeneratedQuestion.model.js`)
    *   Dynamic questions generated by AI to help the user train specific weak areas.
    *   **Fields:** `userId` (ref: User), `topic`, `questionText`, `options` (array of strings), `correctOption`, `explanation`, `generatedAt`.

### API Endpoints

**Base URI**: `/api/v1`

#### Auth Routes (`/api/v1/auth`)
*   `POST /register`: Registers a new user. Expects `name`, `email`, `password`, `targetExam`, `selectedSubjects`.
*   `POST /login`: Authenticates a user. Expects `email`, `password`. Returns a JWT token.

#### Question Routes (`/api/v1/questions`)
*   `GET /`: Fetches a list of questions (supports filters like exam, subject, difficulty). Requires Auth.
*   `GET /:id`: Fetches a single question by its `id`. Requires Auth.
*   `POST /`: Adds a new question. Requires Auth (Admin).
*   `DELETE /:id`: Deletes a question by its `id`. Requires Auth (Admin).

#### Attempt Routes (`/api/v1/attempts`)
*   `POST /start`: Initiates a new practice or mock test session.
*   `POST /submit/:sessionId`: Submits answers and calculates the score. Supports time expiration.
*   `GET /my`: Fetches attempt sessions for the current user.
*   `GET /:sessionId`: Fetches details of a specific attempt session.

#### Analytics Routes (`/api/v1/analytics`)
*   `GET /stats`: Generates overall performance stats (total attempts, average/best score).
*   `GET /weak-areas`: Fetches topics with below 50% accuracy.
*   `GET /subject-wise`: Provides subject-wise accuracy breakdown.
*   `GET /recent-sessions`: Retrieves the 10 most recent attempt sessions.

#### AI Routes (`/api/v1/ai`)
*   `POST /generate`: Uses OpenAI to automatically generate 3 questions per top-3 weakest topics of the user.
*   `GET /my-questions`: Fetches AI-generated questions specific to the user's weak areas.

## 2. Frontend Documentation

The frontend is a single-page application built with React and Vite, focusing on performance and modern developer experience.

### Directory Structure
```
frontend/
├── public/            # Static assets
├── src/
│   ├── assets/        # Images, SVGs, static files
│   ├── App.jsx        # Root component
│   ├── main.jsx       # React entry point
│   ├── index.css      # Global styles
│   └── App.css        # App-specific styles
├── vite.config.js     # Vite configuration
├── eslint.config.js   # ESLint rules
└── package.json
```

### Scripts Available

*   `npm run dev`: Starts the Vite development server with Hot Module Replacement (HMR).
*   `npm run build`: Compiles the application into a production-ready build.
*   `npm run preview`: Bootstraps a local server to preview the production build.
*   `npm run lint`: Runs ESLint to identify code quality issues.
